We run a network of satellite receivers on the volcano: one reference station on the lava plain and rovers up on the edifice, all logging dual-frequency code and carrier phase. I need a node program at `/app/rtk/main.js` that pulls one session for every station off the network's caster and prints a single line of JSON on stdout: an object keyed by rover id, nothing else in it, where each value is an object with `east`, `north` and `up` in mm, the rover's baseline from the reference station. It finds the caster through `CASTER_HOST` and `CASTER_PORT`. `/app/rtk/README.md` covers the caster protocol, the record layouts and the facts the group has collected about its receivers and data.

The grader keeps just the regular `.js`, `.mjs` and `.cjs` files and `package.json` sitting directly in `/app/rtk`, then runs `node main.js` from `/app/rtk` with no arguments, twice, against casters it starts itself. The first serves this session on a different address and port with a smaller per-connection limit. The second serves a session from another of our networks that you don't have, reached by host name, with more satellites and a shorter session than this one (inside the ranges the README gives). It must stay inside that one process the whole time, launching no other program, not even another node.

Each run gets 2 minutes, and by the time it ends the caster must have sent the whole session, every epoch of every station. The answer must list every rover, and a run passes only if east, north and up are each within 30 mm of the true baseline for all of them.
